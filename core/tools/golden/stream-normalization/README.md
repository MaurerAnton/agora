# Stream-normalization golden stand

Pins the C++ port of Agora's **stream post-processing pipeline** — everything between raw
provider events and the normalized downstream events the segment layer consumes:

| Kotlin source | What it owns |
| --- | --- |
| `api/util/ProviderStreamNormalizer.kt` | event routing, thought-metadata projection, native/text tool-call dedup, text-rendered tool-call release |
| `api/util/IncrementalThinkingParser.kt` | incremental lexer for reasoning delimiters (code-fence aware, chunk-boundary safe) |
| `api/util/ThinkingParser.kt`, `api/util/StreamingThinkTagParser.kt` | thin facades over the lexer (see Boundaries) |
| `api/openai/StreamingTextToolCallParser.kt` | streaming text tool-call recovery (tagged / bare-JSON / XML protocols) |
| `api/openai/ToolCallTextParser.kt` (`parse` only) | whole-content tool-call extraction with all-or-nothing semantics |
| `api/util/StreamTermination.kt` | truncation vs retry decision, terminal diagnostics, `carriesModelOutput` |
| `api/util/ToolArgumentAccumulator.kt` | defensive argument accumulation (snapshot vs increment relays) |
| `api/util/MalformedToolCall.kt` | the `agora_malformed_tool_call` stand-in request and its executor result text |
| `api/util/ImplicitThinkingCloseBoundary.kt` | first close marker outside Markdown code (Room projections) |
| `api/util/ProviderRetryPolicy.kt` | retry delays and the HTTP/body/stream retry probes |

The traces are produced by the **real Kotlin sources compiled straight from the app tree**
(`run_golden.sh` lists them); leaf stubs replace Android-only loaders and compile-only
annotations only — no stub participates in a trace. The C++ port must reproduce every trace
byte for byte (`core/tests/stream_normalization_parity_test.cpp`).

## Usage

```bash
KOTLINC=.../kotlinc KOTLINX_JARS=.../json.jar:.../core.jar ./run_golden.sh            # verify
KOTLINC=... KOTLINX_JARS=... ./run_golden.sh --freeze                                 # regenerate
```

Requirements match the other stands (kotlinc + kotlinx-serialization compiler plugin and
jars) plus `kotlinx-coroutines-core-jvm.jar`, which ships inside the kotlinc distribution
(`api/LlmProvider.kt` is compiled real — it defines `toTokenUsage` and the responses-usage
models).

Scenario JSON is regenerated by `genlib.py` + `gen_normalizer.py`, `gen_thinking.py`,
`gen_texttool.py`, `gen_rest.py`, `gen_batch2.py` (run from this directory); payloads that
contain tag markers are assembled from string pieces so no marker is a contiguous literal.

## Modes

Every scenario carries `name` (must equal the file stem) and `mode`:

| mode | exercised API | inputs |
| --- | --- | --- |
| `normalizer` | `ProviderStreamNormalizer.emit/finish` | `tools`, `nativeTextParsingAuthoritative`, `releaseTextTools`, `events[]` |
| `thinkingParser` | `IncrementalThinkingParser.feed/flush` | `chunks[]`, `startInThinking`, `thinkingEnabled`, `flushThinkingEnabled` |
| `textParser` | `StreamingTextToolCallParser.feed/flush` (chunk by chunk) | `chunks[]` |
| `toolParser` | `ToolCallTextParser.parse` | `content` |
| `accumulator` | `ToolArgumentAccumulator.append` | `fragments[]` (null entries pin the null rule) |
| `closeBoundary` | `findImplicitThinkingClose` | `text` |
| `termination` | `StreamTermination` predicates + `toError` | `sawTerminalMarker`, `stopReason`, `producedContent`, `toolCallInFlight`, `hasStreamError`, `streamErrorMessage`, `alreadyReportedError`, `timedOut`, `retryableStreamError` |
| `malformed` | `malformedToolCallRequest` + `malformedToolCallResultText` | `cause`, `originalName`, `originalArguments`, `streamKey`, `signature` |
| `carriesOutput` | `StreamEvent.carriesModelOutput` | `events[0]` |
| `retry` | `ProviderRetryPolicy` | `retryNumber`, `statusCode`, `body`, `streamErrorMessage`, `retryableStatusCodes` |

Event objects in `events[]`/`calls[]`: `type` ∈ `text`, `thought`, `toolCall`, `toolCalls`,
`error`, `usage`, `retrying`, `toolCallUpdate`, `hosted`, `citation`, plus the matching
fields (`text`, `thought`, `title`, `signature`, `id`, `name`, `arguments`, `streamKey`,
`tokenCount`, `attempt`, `maxAttempts`, `result`, `isError`, `calls`).

## Trace format

Pipe-separated lines, header `name|<name>` and `mode|<mode>`; a trailing
`error|<ExceptionSimpleName>` appears only when the API under test throws (the exception
class alone is the contract — message text is not pinned).

Escaping in field position: `\\` → `\\`, `|` → `\p`, `;` → `\s`, newline/CR/tab →
`\n`/`\r`/`\t`; absent optional strings print `-`.

Key lines (C++ parity test mirrors them exactly):

- normalizer downstream: `text|`, `thought|<text>|<title>|<signature>`,
  `toolCall|<id>|<name>|<args>|<sig>|<streamKey>|<outputItems>`,
  `toolCalls|<n>` + n × `toolCall|…`, `error|<kind>…`, `usage|<total>|<reasoning>`,
  `retrying|<attempt>|<max>`, `toolCallUpdate|…`, `hosted|…`, `citation`
- thinking: per chunk `chunk|<i>` then `text|`/`thought|` emitted by that chunk, then
  `pending|<buffer>`; `flush`, final `pending|`, `inThinking|0|1`
- textParser: `text|`, `update|<key>|<name>|<args>`,
  `complete|<key>|<id>|<name>|<args>`, `malformed|<cause>`
- toolParser: one `call|<id>|<name>|<args>` per result, or `calls|0`
- accumulator: `value|<accumulated>`, `empty|0|1`
- closeBoundary: `boundary|<start>|<endExclusive>` or `boundary|none`
- termination: `truncated|0|1`, `retryable|0|1`, `error|none` or `error|<kind>…`
- malformed: `event|<id>|<name>|<argsJson>|<sig>|<streamKey>`, `result|<text>`
- carriesOutput: `output|0|1`
- retry: `delay|<ms>`, `upstreamFailure|0|1`, `retryHttp|0|1`, `streamRetry|0|1`

### UUID normalization

Generated ids are nondeterministic, so the driver normalizes before writing:

- any dashed UUID (8-4-4-4-12 hex) → `<uuid>` — covers `call_text_<uuid>` ids and
  `text_tool_<uuid>` stream keys
- the compact-32hex families `call_malformed_<32hex>` and `malformed_tool_<32hex>` →
  `…​<uuid>` (prefix-anchored so deterministic hex in scenario inputs is never swallowed)

## Boundaries (documented scope, not stubs)

- **`OpenAiResponsesEventRouter`** (same file as `ToolCallTextParser`) is the Responses-API
  branch — it compiles in the stand but no scenario exercises it; it belongs to the
  responses-branch slice that stays on Kotlin.
- **`ThinkingParser` / `StreamingThinkTagParser` facades** are pass-through delegation
  (including the `flush(thinkingEnabled = null)` overload choice). The lexer behavior behind
  both overloads is scenario-pinned here; the delegation itself is unit-pinned in the C++
  port tests.
- **`ToolSchemaJson`** is provider-request-side (Anthropic/Gemini schema conversion), not
  part of the stream pipeline — future provider-request slice.
- **`ProviderRetryPolicy.retryableStatusCodes`** is a caller-supplied set (transport policy);
  the stand pins the probe functions given an explicit set.
- **Retry/HTTP transport and viewmodel segment assembly** are outside this module.
- **`GenerationError` exception mapping** in `StreamTermination`'s file (the `throwable →
  GenerationError` helpers) is transport-coupled (Java exception types) and stays Kotlin;
  `StreamTermination`'s own predicates and `toError` are pinned here.
- **Case-insensitive marker matching** in the C++ port folds ASCII only. Kotlin's
  `Char.equalsIgnoreCase` additionally equates a few exotic characters to ASCII letters
  (U+0131 `ı`≈`i`, U+212A `K`≈`k`, U+017F `ſ`≈`s`); those equivalences are not reproduced —
  every pinned scenario and every plausible model-emitted marker is ASCII.
- **UTF-16 vs UTF-8**: the port operates on UTF-8 bytes, which is output-equivalent for this
  module's ASCII markers, per-code-point iteration, ASCII case folding and byte-slicing at
  ASCII boundaries. Kotlin's UTF-16-unit `.take(200/2000)` in `MalformedToolCall` is mirrored
  with `json::take_utf16_units`.
